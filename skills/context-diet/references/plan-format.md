# Plan file format

`.claude/context-diet-plan.md` is both the human review artifact and the input
`apply.py` parses. The syntax below is strict — deviate and blocks are skipped.

The user is expected to edit `verdict` lines (and occasionally `dest`, `paths`,
or `pointer`) before approving. Everything else is yours to write.

## Parser contract

- A decision starts at a line matching `### <ID>` where `<ID>` is `B` followed
  by digits, e.g. `### B07`. Anything after the ID on that line is a human
  title and is ignored by the parser.
- Fields are lines of the exact form `- **key:** value`, one per line.
- Parsing of a decision ends at the next `###` or `##` heading.
- Unknown keys are ignored. Missing required keys make the block an error,
  reported and skipped — never guessed at.
- Block IDs must exist in `blocks.json` from Phase 0. IDs are not invented.
- Everything outside `## Decisions` is free-form prose for humans.

## Fields

| Key | Required for | Value |
|---|---|---|
| `file` | all | Source file, as it appears in `blocks.json` |
| `verdict` | all | One of `KEEP` `RULE` `REFERENCE` `SKILL` `NESTED` `DELETE` `ARCHIVE` `POINTER` `ASK` |
| `critical` | all | `yes` or `no` — result of the criticality gate |
| `why` | all | One sentence. The reason, not a restatement of the block |
| `evidence` | all non-`KEEP` | The check you ran and its result |
| `dest` | `RULE` `REFERENCE` `NESTED` `ARCHIVE` `POINTER` | Destination path, relative to root. For `POINTER` it must already exist |
| `paths` | `RULE` | Comma-separated globs |
| `name` | `SKILL` | Skill directory name, kebab-case |
| `description` | `SKILL` | The skill's triggering description |
| `pointer` | `REFERENCE` `POINTER` | The trigger-stating sentence for the index |
| `hook` | optional | Suggested `PreToolUse` / `permissions.deny` equivalent |

Constraints enforced by `apply.py`:

- `critical: yes` forces `verdict: KEEP`. A critical block routed anywhere else
  is a hard error, not a warning.
- `pointer` must contain the `dest` path wrapped in backticks. An unbackticked
  path becomes an `@import` candidate and is rejected.
- No value may contain an unbackticked `@`-prefixed path.
- `ASK` blocks are left untouched and reported as unresolved.
- `POINTER` writes nothing to `dest`, so `dest` must already exist. A missing
  target is a hard error: the block would be removed and the pointer would lead
  nowhere. Use `REFERENCE` when the content still has to be moved.
- A destination may not be a file the same plan removes blocks from. A file
  that merely *has* blocks is fine — an imported doc is a source yet is the
  correct `POINTER` target.

### Example: undoing an `@import`

````markdown
### B14 · Architecture Overview
- **file:** CLAUDE.md
- **verdict:** POINTER
- **critical:** no
- **dest:** PRPs/ai_docs/ARCHITECTURE.md
- **pointer:** For system architecture and how the services fit together, read `PRPs/ai_docs/ARCHITECTURE.md`.
- **evidence:** @import costing 1,459 eager tokens; the file already exists
- **why:** The import loads the whole document every session; backticking the path makes it a reference.
````

## Template

````markdown
# context-diet plan

<!-- generated by context-diet -->
<!-- Edit any `- **verdict:**` line, then say "apply". -->

## Summary

Eager context today: **4,180 tokens** across 3 files.
Projected after: **1,240 tokens** (−70%).

| Verdict | Blocks | Eager tokens freed |
|---|---|---|
| KEEP | 9 | — |
| RULE | 6 | 980 |
| SKILL | 2 | 1,110 |
| REFERENCE | 3 | 540 |
| DELETE | 4 | 310 |
| ASK | 2 | — |

## Open questions

1. B14 and B31 contradict each other on branch naming. Which is current?
2. B22 documents a `staging` deploy — I cannot find any staging config. Dead?

## Decisions

### B03 · Testing conventions
- **file:** CLAUDE.md
- **verdict:** RULE
- **critical:** no
- **dest:** .claude/rules/testing.md
- **paths:** tests/**/*.py, src/**/*_test.py
- **evidence:** 41 of 612 tracked files match (6.7%); `pytest` in pyproject dev-deps
- **why:** Applies only to test files, so it should load only when Claude opens one.

### B08 · Release process
- **file:** CLAUDE.md
- **verdict:** SKILL
- **critical:** no
- **name:** cut-release
- **description:** Cut and publish a release — version bump, changelog, tag, and npm publish. Use when asked to release, ship a version, cut a tag, or publish to npm.
- **evidence:** 7-step ordered procedure; no existing skill matches (checked 81 installed skills)
- **why:** A multi-step procedure needed a few times a year, not every session.

### B11 · Never force-push to main
- **file:** CLAUDE.md
- **verdict:** KEEP
- **critical:** yes
- **hook:** PreToolUse on Bash matching `push .*--force`
- **why:** Irreversible and shared; must survive /compact, so it stays in root.

### B17 · Project structure
- **file:** CLAUDE.md
- **verdict:** DELETE
- **critical:** no
- **evidence:** Lists 11 directories; all 11 exist and are discoverable via one Glob. Two listed dirs (`src/legacy/`, `bin/`) no longer exist.
- **why:** Derivable from the repo and already partly stale. The one non-obvious line is preserved as B18.

### B24 · Environment variables
- **file:** CLAUDE.md
- **verdict:** REFERENCE
- **critical:** no
- **dest:** .claude/references/env-vars.md
- **pointer:** When adding, renaming, or debugging an environment variable, or editing `.env*`, read `.claude/references/env-vars.md`.
- **evidence:** 34-line table, ~430 tokens; referenced by no other instruction
- **why:** Consulted occasionally, never followed as a rule.
````

## Writing the digest

After writing the plan, the chat message should be short: the two token
numbers, the verdict counts, and every `ASK` phrased as an actual question the
user can answer in one line. Do not repeat the plan in chat — that is what the
file is for.
